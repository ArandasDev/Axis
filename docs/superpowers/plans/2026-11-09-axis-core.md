# Axis, plano 1: workspace + `axis-core` (pipeline de ajustes)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** criar o workspace Cargo do Axis e o crate `axis-core`, que contém o estado de entrada normalizado, os modelos de configuração (perfil e correções do controle) e o pipeline de ajustes completo (calibração → drift → deadzone → curva → remapeamento, mais os gatilhos), com modo inspeção, testes de propriedade e benchmark.

**Architecture:** `axis-core` é lógica pura, sem I/O e sem dependência de hardware. As configurações (`Profile`, `Corrections`) são structs `serde` validadas. `Pipeline::compile` transforma essas configurações em parâmetros de tamanho fixo (sem `Vec`) para que `Pipeline::process` rode sem alocar. Cada etapa é um módulo com uma função pura.

**Tech Stack:** Rust 1.99 (edition 2024), `serde` 1 + `toml` 0.8, `thiserror` 2, `proptest` 1 e `criterion` 0.5 (dev).

**Spec:** `docs/superpowers/specs/2026-11-09-axis-design.md` (seções 3, 5.1, 6 e 9 são as que este plano implementa).

## Roteiro dos planos

A spec cobre vários subsistemas. Cada plano entrega software testável por conta própria:

1. **Este plano:** workspace + `axis-core`. Não depende de hardware nem dos spikes.
2. **Fase 0, spikes** (a: ViGEm + HidHide; b: Xbox; c: fidelidade do Slint). Rodam com os controles reais e produzem respostas, não código mantido. O resultado alimenta os planos 3 a 5.
3. **`axis-devices`:** DS4 e DualSense (USB e BT), identidade por MAC, hotplug, gravação e replay.
4. **`axis-virtual` + `axis-daemon`:** ViGEm, HidHide, threads por controle, período de graça, persistência, bandeja.
5. **`axis-protocol` + `axis-ui`:** named pipe, interface Slint com o design adotado, assistentes de correção.

## Global Constraints

- Edition 2024, `resolver = "3"`, workspace em `crates/*`.
- `axis-core` não depende de nenhum crate de I/O, de plataforma ou de hardware. Dependências permitidas: `serde`, `thiserror` (e `toml` só como dev-dependency).
- Nenhuma alocação de heap em `Pipeline::process` / `process_traced`. Os parâmetros compilados usam arrays de tamanho fixo.
- Toda saída de eixo fica em [−1, 1]; todo gatilho em [0, 1]; a deadzone e a curva nunca invertem o sinal ou a direção; entrada dentro da zona interna → saída exatamente 0.0; o pipeline é determinístico (spec 6.2).
- Meta de desempenho: `Pipeline::process` < 5 µs por pacote (spec 9).
- Diretório de build fora do OneDrive: `C:/dev/cargo-target/axis` (spec 12).
- Git: Conventional Commits, branch `feat/axis-core`, autor único, **sem trailers `Co-Authored-By` nem linhas de atribuição**.
- Identificadores no código em inglês. Docs e mensagens de commit podem ser em português.

## Review Focus

1. **NaN ou infinito vindo do driver** (report corrompido): o pipeline trata como 0.0 e nunca propaga NaN para a saída. Teste na Task 7.
2. **Valor cru fora de [−1, 1] ou de [0, 1]** (clone de DS4, firmware estranho): é limitado antes da calibração. Teste na Task 2 (stick) e na Task 5 (gatilho).
3. **Ângulo na fronteira ±π** (stick totalmente à esquerda): a interpolação entre setores dá a volta corretamente, sem pular de setor. Teste na Task 2.
4. **Perfil degenerado editado à mão** (inner ≥ outer, pontos de curva com x repetido, `rest >= max`): `validate` rejeita com um erro que nomeia o campo, e `Pipeline::compile` nunca produz divisão por zero. Testes na Task 6.
5. **TOML de uma versão de esquema mais nova** que a suportada: retorna um erro explícito em vez de ler errado em silêncio. Teste na Task 6.

### Task 2: etapa de calibração do stick

**Files:**
- Create: `crates/axis-core/src/stages/mod.rs`, `crates/axis-core/src/stages/calibration.rs`

**Interfaces:**
- Consumes: `Vec2` (Task 1).
- Produces:
  - `pub const SECTORS: usize = 16;`
  - `#[derive(Clone, Copy, Debug, PartialEq)] pub struct CalibrationParams { pub center: Vec2, pub outer_radius: [f32; SECTORS] }`, com `Default` = centro (0, 0) e todos os raios 1.0.
  - `pub fn calibrate(raw: Vec2, p: &CalibrationParams) -> Vec2`

Algoritmo (não é determinado pela assinatura):
1. Limitar `raw.x` e `raw.y` a [−1, 1].
2. `v = raw − center`. Se `|v| == 0`, retornar zero.
3. Ângulo `a = atan2(v.y, v.x)` normalizado para [0, 2π). O setor `i` cobre o ângulo `i · 2π/16` (o raio medido *naquela direção*). Posição contínua `s = a / (2π/16)`; `i0 = floor(s) % 16`, `i1 = (i0 + 1) % 16`, `t = s − floor(s)`; `r = lerp(outer_radius[i0], outer_radius[i1], t)`.
4. `v = v / r`; se `|v| > 1`, normalizar para comprimento 1.

### Task 3: etapas de drift e deadzone

**Files:**
- Create: `crates/axis-core/src/stages/drift.rs`, `crates/axis-core/src/stages/deadzone.rs`

**Interfaces:**
- Consumes: `Vec2`.
- Produces:
  - `pub fn drift(v: Vec2, radius: f32) -> Vec2`: se `|v| <= radius` → zero; senão, reescala a magnitude de [radius, 1] para [0, 1] mantendo a direção.
  - `#[derive(Clone, Copy, Debug, PartialEq, Eq, Serialize, Deserialize)] pub enum DeadzoneMode { Radial, Axial }`
  - `#[derive(Clone, Copy, Debug, PartialEq)] pub struct DeadzoneParams { pub mode: DeadzoneMode, pub inner: f32, pub outer: f32, pub anti: f32 }`
  - `pub fn deadzone(v: Vec2, p: &DeadzoneParams) -> Vec2`
  - `pub(crate) fn shape(m: f32, inner: f32, outer: f32, anti: f32) -> f32`: para magnitude `m >= 0`, retorna 0 se `m <= inner`, senão `anti + (1 − anti) · clamp((m − inner)/(outer − inner), 0, 1)`. Pré-condição: `inner < outer` (garantida por `validate`, Task 6).
  - Radial: aplica `shape` à magnitude e mantém a direção. Axial: aplica `shape(|x|)` e `shape(|y|)` separadamente, preservando os sinais.

### Task 6: modelos de configuração, validação e esquema

**Files:**
- Create: `crates/axis-core/src/settings.rs`, `crates/axis-core/src/error.rs`

**Interfaces:**

  - `pub const SCHEMA_VERSION: u32 = 1;`
  - `pub enum CurveSpec { Linear, Exponent { e: f32 }, Points { points: Vec<[f32; 2]> } }` (`#[serde(tag = "kind", rename_all = "snake_case")]`)
  - `pub struct DeadzoneSpec { pub mode: DeadzoneMode, pub inner: f32, pub outer: f32, pub anti: f32 }`. Default: `Radial`, 0.05, 1.0, 0.0.
  - `pub struct StickSettings { pub deadzone: DeadzoneSpec, pub curve: CurveSpec }`
  - `pub struct TriggerSettings { pub inner: f32, pub curve: CurveSpec, pub hair_trigger: Option<f32> }`. Default: 0.0, Linear, None.
  - `pub struct Profile { pub schema_version: u32, pub name: String, pub left_stick: StickSettings, pub right_stick: StickSettings, pub l2: TriggerSettings, pub r2: TriggerSettings, pub button_map: BTreeMap<Button, Button>, pub disabled_buttons: BTreeSet<Button>, pub vibration: f32 }`. Default: name `"Padrão"`, `button_map` e `disabled_buttons` vazios (= identidade), vibration 1.0.   - `Option<f32>` em structs usa `#[serde(default, skip_serializing_if = "Option::is_none")]`.
  - `pub struct StickCorrection { pub center: [f32; 2], pub outer_radius: [f32; 16], pub drift_radius: f32 }`. Default: [0, 0], todos 1.0, 0.0.
  - `pub struct TriggerCalibration { pub rest: f32, pub max: f32 }`. Default: 0.0, 1.0.
  - `pub struct Corrections { pub left: StickCorrection, pub right: StickCorrection, pub l2: TriggerCalibration, pub r2: TriggerCalibration }`
  - `pub enum DeviceFamily { DualShock4, DualSense, Xbox }`
  - `pub struct ControllerRecord { pub schema_version: u32, pub id: String, pub family: DeviceFamily, pub owner_name: String, pub owner_color: [u8; 3], pub active_profile: String, pub corrections: Corrections }`
  - `impl Profile { pub fn validate(&self) -> Result<(), ValidationError> }` e `impl Corrections { pub fn validate(&self) -> Result<(), ValidationError> }`
  - `pub fn check_schema(found: u32) -> Result<(), SchemaError>`: aceita `1..=SCHEMA_VERSION`.
  - `error.rs`: `#[derive(Debug, thiserror::Error, PartialEq)] pub struct ValidationError { pub field: String, pub reason: String }` (Display: `"{field}: {reason}"`), e `pub enum SchemaError { TooNew { found: u32, supported: u32 }, Zero }`.

Regras de validação (o campo no erro usa caminho com pontos, como `left_stick.deadzone.inner`):
- deadzone: `0 ≤ inner < outer ≤ 1`, `0 ≤ anti < 1`.
- curva: `Exponent` com `0.2 ≤ e ≤ 5.0`; `Points` com 1 a 8 pontos, x estritamente crescente em (0, 1), y não decrescente em [0, 1].
- gatilho: `0 ≤ inner < 1`; `hair_trigger` em (0, 1].
- `vibration` em [0, 1].
- correção: cada coordenada de `center` com `|c| < 0.5`; `outer_radius` em [0.3, 1.5]; `drift_radius` em [0, 0.5]; `0 ≤ rest < max ≤ 1`.
- qualquer `f32` não finito é inválido.
